最初にプロジェクトへ小さな機能を追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は組織で既に使われているワークフローに沿って動作し、適切な方法で必要な機能を作れるよう支援します。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを進めます。Issue を起点に新機能を作り、コードの妥当性と機能の動作を確認し、最後にプロジェクトへマージします。

> [!NOTE]
> 機能開発を進める間は、同じ会話とブランチを使います。通常、ファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主な概念に集中できるよう簡略化しています。

このレッスンでは、次の内容を学習します。

- GitHub Issue から Copilot の新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- ポートフォワードしたブラウザーで機能を手動で検証します。

この機能の開発を続ける中で、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がカテゴリとパブリッシャーでゲームを絞り込める必要があります。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで方針を決めた後、範囲を定めた実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発ワークフローに導入しても、基本的な考え方は変わりません。むしろ、いっそう重要になります。多くの開発者は、次のような流れで作業します。

1. 実装する内容を記載した Issue から始めます。
2. 実装内容の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行し、コードを検証します。
5. 新しい機能を手動で検証します。
6. pull request (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって詳細は異なりますが、ほとんどの場合は上記の流れを基本にしています。

この標準的な手順に従うと、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューと検証を受けるようにできます。

## 会話モード

**会話モード**はエージェントの自律性を制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成し、プロジェクトファイルの編集は行いません。
- **Autopilot**: エージェントがコードの作成、テストの実行、反復的な修正を行い、タスクが完了するまで自律的に作業します。

最初は Plan モードで計画を確認し、その後 Autopilot で実装します。

## Issue から始める

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの Issue を選びます。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) から始まっていることを確認してください。`#` を使うと、GitHub 上の Issue や pull request (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、機能を実装したりタスクを実行したりする方針を決めてから、Copilot に作業を任せられます。複雑な作業では、時間をかけて計画を立てると効果的です。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した Issue の参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査して、実装に適した方法を判断し、計画を作成します。

3. フィルターの動作について質問された場合は、希望に沿って回答します。正解は 1 つではありません。
4. 計画ができたら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して、計画全体を表示します。
5. 計画を上下にスクロールしてレビューします。
6. 自分の決定と合わない部分があれば、Copilot に計画を修正するよう依頼します。

## Autopilot を承認する

計画の作成とレビューが終わったら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot では、Copilot がタスクを完了したと判断するまで、問題への取り組みを繰り返します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンで同様の名前が付いた選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿ってコードを生成し、テストを実行しながら作業する様子を確認します。

> [!NOTE]
> 承認すると実装がすぐに始まることがあります。先に計画をレビューしてください。依存関係が不足している場合やポートが競合している場合は、チェック完了と見なす前にセットアップの問題を解決します。

## 実装をレビューして検証する

コードの生成後、他のコードと同様にマージする前にレビューします。コードを確認し、サイトを起動して問題がないことを確かめましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** が表示されていないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 変更内容を Issue と計画中に決めた方針に照らして確認します。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分表示を終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を確認する

コードに問題がないことを確認できました。次に、アプリを起動し、前回と同じように Codespaces のポートフォワード経由でサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリとパブリッシャーのフィルター、およびその組み合わせを試します。
4. リセットと結果が空の場合の動作が、Issue と決定した内容に沿っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を構築し、レビューしました。このレッスンでは、次の作業を行いました。

- Plan モードで要件を定義しました。
- Autopilot モードで新しい機能を実装しました。
- コードをレビューしました。
